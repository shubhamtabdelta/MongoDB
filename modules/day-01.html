1. Database, DBMS and RDBMS

Database – kya hai?

A database is an organized place where data is stored so we can add, read, update and delete it easily. Simple words me: data ka digital godown.

DBMS – kya hai? Kya karta hai?

DBMS (Database Management System) is software that manages the database. It stores data, protects it, lets many users use it at the same time, and gives us a way to ask questions (queries). Example: MongoDB, MySQL, PostgreSQL.

RDBMS – kya hai?

RDBMS (Relational DBMS) stores data in tables (rows and columns). Tables are connected using keys (primary key and foreign key). It uses SQL to talk to data. Example: MySQL, PostgreSQL, Oracle.

Example

A school keeps student records. Without a database, they use paper registers. With a database, one search gives any student’s data in a second.

Students table (RDBMS)
id | name  | city
1  | Riya  | Surat
2  | Amit  | Navsari

Interviewer ko aise batao (ready definition)

Database: A database is an organized collection of data that is stored electronically, so that it can be easily accessed, managed and updated.

DBMS: A DBMS (Database Management System) is software used to create, store, manage and secure a database. It lets users and applications work with the data safely.

RDBMS: An RDBMS (Relational DBMS) is a type of DBMS that stores data in tables made of rows and columns. Tables are linked using primary and foreign keys, and we query them using SQL. Examples are MySQL and PostgreSQL.

2. NoSQL and Document Databases

NoSQL – kya hai?

NoSQL means “Not Only SQL”. These databases do not need fixed tables. Data can be stored in other shapes, so they are flexible and easy to scale.

NoSQL ke types

  • Document – JSON-like documents. Example: MongoDB.
  • Key-Value – simple key and value. Example: Redis.
  • Column-family – data in wide columns. Example: Cassandra.
  • Graph – nodes and relationships. Example: Neo4j.

Document database – kya hota hai?

A document database stores each record as one document, like a small JSON object. All related data of one thing stays together, so you often need no JOIN.

Example

An online store product has different fields. A phone has ram and a shirt has size. In a table you need many empty columns. In a document DB each product keeps only its own fields.

{ "name": "Phone X", "price": 15000, "ram": "8GB" }
{ "name": "T-Shirt", "price": 499, "size": "M", "color": "blue" }

Interviewer ko aise batao (ready definition)

NoSQL: NoSQL databases are non-relational databases. They store data in flexible formats such as documents, key-value pairs, columns or graphs, and they scale horizontally.

Document database: A document database stores each record as a self-contained document, usually JSON-like. All related data can be kept together in one document, so we often do not need JOINs. MongoDB is the most popular example.

Same query in both

-- SQL
SELECT * FROM students WHERE city = 'Surat';

// MongoDB
db.students.find({ city: "Surat" })
Yaad rakho: Koi bhi “best” nahi hai. Strict data aur bahut relations ho to SQL. Flexible data aur fast change ho to MongoDB.

Interviewer ko aise batao (ready definition)

SQL vs NoSQL: SQL databases are relational, use tables with a fixed schema and scale mostly vertically. NoSQL databases are non-relational, have a flexible schema and scale horizontally.

MongoDB vs SQL databases: MongoDB stores BSON documents in collections with a flexible schema, and we embed related data. SQL databases store rows in tables with a fixed schema, and we use JOINs to connect related data.

Document – kya hai?

One record stored as field-value pairs. It can hold text, numbers, arrays and even other documents.

Collection – kya hai?

A group of documents. It does not force the same fields on every document.

Example

Database: school
  Collection: students
    { "_id": 1, "name": "Riya", "city": "Surat", "marks": [80, 90] }
    { "_id": 2, "name": "Amit", "city": "Navsari" }

Dekho, Amit ke document me marks nahi hai, aur koi error nahi aata.

Interviewer ko aise batao (ready definition)

Database (in MongoDB): A database is the top-level container that holds collections.

Collection: A collection is a group of related documents inside a database. It is like a table in SQL, but it does not enforce a fixed schema.

Document: A document is a single record in MongoDB, made of field-value pairs. It is like a row in SQL, but it can contain arrays and nested documents.

5. JSON vs BSON and ObjectId

JSON – kya hai?

JSON (JavaScript Object Notation) is a human-readable text format for data. Example: {"name":"Riya","age":20}

BSON – kya hai? Kya karta hai?

BSON means “Binary JSON”. MongoDB stores data internally in BSON. It is binary, so it is faster for the computer to read and write. It also supports extra types that JSON does not have, like Date, ObjectId, Decimal128 and Binary.

PointJSONBSON
FormatTextBinary
Readable by humanYesNo (tools show it as JSON)
Data typesString, number, boolean, null, array, objectAll of JSON + Date, ObjectId, Int32, Int64, Decimal128, Binary
Used forAPIs, config, data exchangeStorage and transfer inside MongoDB

ObjectId – kya hota hai?

Every document needs a unique _id. If you do not give one, MongoDB creates an ObjectId, a 12-byte value shown as 24 hex characters.

ObjectId("652f1c2a9b1e8a3d4c5f6a7b")

Inside the 12 bytes:
4 bytes  = timestamp (creation time)
5 bytes  = random value
3 bytes  = counter

Fayda: It is unique without asking a central server, and it roughly sorts by creation time.

db.students.insertOne({ name: "Riya" })
// MongoDB adds: _id: ObjectId("...") automatically

Interviewer ko aise batao (ready definition)

JSON: JSON (JavaScript Object Notation) is a lightweight, human-readable text format used to store and exchange data as key-value pairs.

BSON: BSON (Binary JSON) is the binary format MongoDB uses to store documents. It is faster to parse than JSON and supports more data types, like Date, ObjectId and Decimal128.

ObjectId: ObjectId is a 12-byte unique identifier that MongoDB generates by default for the _id field. It contains a timestamp, a random value and a counter.

7. MongoDB Architecture and Use Cases

MongoDB – kya hai?

MongoDB is an open-source, document-oriented NoSQL database. It stores data as BSON documents in collections.

Architecture – main parts

  • Client / App – your Node.js, Python or Java app, or mongosh and Compass.
  • mongod – the database server process that stores and serves data.
  • Storage engine (WiredTiger) – writes data to disk, handles compression and concurrency.
  • Replica Set – copies of the same data on 3 or more servers (1 primary + secondaries). If the primary fails, a secondary becomes primary. This gives high availability.
  • Sharding – splits big data across many servers (shards). This gives horizontal scaling. mongos is the router and config servers keep the map.
  • Indexes – make queries fast, like a book’s index.
App --> mongos (router) --> Shard 1 (Replica Set)
                       --> Shard 2 (Replica Set)
                       --> Shard 3 (Replica Set)

Use cases

  • E-commerce product catalog (products have different fields)
  • Content management, blogs, news apps
  • Real-time apps: chat, IoT sensor data, logs
  • User profiles and personalization
  • Mobile app backends

Interviewer ko aise batao (ready definition)

MongoDB: MongoDB is an open-source, document-oriented NoSQL database. It stores data as flexible BSON documents inside collections, and it is built for high performance, high availability and horizontal scaling.

MongoDB architecture: A client application connects to the mongod server, which uses the WiredTiger storage engine. For high availability we use a replica set (one primary and several secondaries). For scaling we use sharding, where mongos routes queries to different shards.

Use cases: MongoDB is a good fit for product catalogs, content management, real-time apps, IoT and log data, user profiles, and mobile app backends, where data is flexible and grows fast.

Practice Tasks – Answers

Task 1. Explain MongoDB in your own words

MongoDB is a NoSQL database that saves data as flexible JSON-like documents instead of rows in tables. Documents live in collections, and collections live in a database. You do not need to design a fixed schema first, so changing the app is easy. It is fast, scales across many servers, and is popular for modern web and mobile apps.

Task 2. Install MongoDB and Compass, or use Atlas

Option A – Atlas (easiest, no install):

  1. Go to mongodb.com/atlas and sign up.
  2. Create a free M0 cluster.
  3. Create a database user (username and password).
  4. In Network Access, add your IP address.
  5. Click Connect and copy the connection string, then paste it in Compass or mongosh.

Option B – Local install:

  1. Download MongoDB Community Server and install it (select “Run as service”).
  2. Install MongoDB Compass (usually comes with the installer).
  3. Install mongosh if it is not included.
  4. Connect with this string:
mongodb://localhost:27017

Test it: run mongosh, then db.runCommand({ ping: 1 }). If you see { ok: 1 }, setup is done.

Task 5. When is a document database suitable?

Use it when:

  • Data shape changes often or each item has different fields (product catalog).
  • Data is naturally nested, like an order with items and address.
  • You need fast reads of a whole object in one query.
  • You expect big data and need to scale across servers.
  • You want to build quickly (startups, prototypes, MVPs).

Avoid it (or be careful) when:

  • Data has many complex relations and heavy JOINs (for example, accounting).
  • You need strict rules and multi-table transactions everywhere.

Interview Questions and Answers

Q1. What is MongoDB?

MongoDB is an open-source, document-oriented NoSQL database. It stores data as BSON documents inside collections. It is flexible, fast and scalable.

Q2. What is the difference between SQL and NoSQL?

SQL databases use tables with a fixed schema and SQL language. NoSQL databases use flexible models (document, key-value, graph, column) and usually scale horizontally. Example: MySQL is SQL and MongoDB is NoSQL.

Q3. What is a document and what is a collection?

A document is one record made of field-value pairs. A collection is a group of documents, like a table in SQL. A database holds many collections.

Q4. Do MongoDB collections need a fixed schema?

No. Documents in the same collection can have different fields. But you can add schema validation rules if you want some structure.

Q5. What is the difference between JSON and BSON?

JSON is text and human-readable. BSON is binary, faster to parse, and supports extra types like Date, ObjectId and Decimal128. MongoDB stores BSON but shows it to us as JSON.

Q6. What is ObjectId?

It is the default 12-byte unique value MongoDB puts in the _id field. It contains a timestamp (4 bytes), a random value (5 bytes) and a counter (3 bytes). It is shown as 24 hex characters.

Q7. What is the _id field? Can we change it?

_id is the primary key of every document and must be unique in a collection. We can give our own value (like an email or number) when inserting. After the document is created, _id cannot be changed.

Q8. What are Atlas, Compass and mongosh?

Atlas is MongoDB’s cloud service. Compass is the GUI tool. mongosh is the command-line shell. Community Server is the free database you install locally.

Q9. What is a replica set?

A group of MongoDB servers holding the same data: one primary and the rest secondaries. If the primary goes down, one secondary is elected as the new primary. It gives high availability.

Q10. What is sharding?

Sharding splits a large collection across multiple servers using a shard key. It is MongoDB’s way of horizontal scaling.

Q11. Does MongoDB support JOINs and transactions?

Yes. $lookup in the aggregation pipeline works like a JOIN. Multi-document ACID transactions are supported since MongoDB 4.0. But the best practice is to embed related data, so you need them less.

Q12. When would you choose MongoDB over MySQL?

When data is flexible or nested, requirements change fast, or you need to scale out easily. Examples: product catalogs, content apps, IoT and logs. For strict relational data like banking, MySQL or PostgreSQL is often better.

Q13. What are the disadvantages of MongoDB?

Data can be duplicated because of embedding, so updates need care. Complex JOINs are less natural than SQL. It can use more memory. Without good design, data can become messy.

Q14. What is the default port of MongoDB?

27017.

Q15. What is the difference between embedding and referencing?

Embedding: store related data inside one document (fast reads, good for “one-to-few”). Referencing: store the _id of another document (good for “one-to-many” or very large data, needs extra query or $lookup).
